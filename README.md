# Algoritm-task-3
Доступ по индексу показывает практически постоянное среднее время при росте N от 10 до 128 000, что подтверждает гипотезу O(1): адрес элемента вычисляется за константное число операций.

Бинарный поиск демонстрирует очень медленный рост времени — при увеличении N в 12 800 раз время выросло лишь в несколько раз, что качественно согласуется с O(log N).

Линейный поиск растёт линейно: в худшем случае (отсутствующий элемент) время пропорционально N, в лучшем (первый элемент) — практически не зависит от N, что подтверждает различие лучшего/среднего/худшего случаев.

Подсчёт по условию всегда проходит весь массив, поэтому время линейно растёт при любом распределении данных; различия между случаями минимальны, что ожидаемо для O(N).

Для поиска максимума также наблюдается линейный рост; убывающий массив (худший случай по числу обновлений максимума) оказался немного медленнее возрастающего, что связано с дополнительными операциями присваивания и предсказанием ветвлений.

Разброс значений внутри одного N (5 замеров) заметен из‑за кэширования, JIT‑компиляции и шума ОС; поэтому для выводов использовалось среднее по нескольким прогонам после прогрева.

В целом экспериментальные графики соответствуют теоретическим оценкам: константа для индексации, логарифм для бинарного поиска, линейная зависимость для линейного поиска, подсчёта и поиска максимума; отклонения объясняются накладными расходами JVM и особенностями памяти.
